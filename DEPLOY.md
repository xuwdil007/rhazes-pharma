# Развёртывание РАЗЕС ФАРМА

Docker собирает React/Vite и Go API в один образ. В серверной сборке отключён
статический режим GitHub Pages: CMS и отклики сохраняются на сервере.
Нужны Docker Engine и Docker Compose v2. Команды выполняются из папки проекта.

## Настройки

```bash
cp .env.example .env
```

В Windows PowerShell вместо `cp` можно использовать `Copy-Item .env.example .env`.
Задайте в `.env` собственные `ADMIN_LOGIN`, `ADMIN_PASSWORD` и `ADMIN_SECRET`.
Не используйте значения из примера. Секрет можно создать командой
`openssl rand -hex 32`. Не публикуйте `.env` в Git.

## Локальная проверка

```bash
docker compose up -d --build
docker compose ps
docker compose logs -f app
```

Сайт: http://localhost:8080/ — админка: http://localhost:8080/#/admin.
Вход с логином и паролем из `.env`. Node.js и Go на сервер устанавливать не нужно.

## Сервер с доменом и HTTPS

1. Скопируйте проект на сервер (без `node_modules`, `.env` и персональных данных).
2. Создайте `.env` и задайте свои пароль и секрет.
3. Направьте DNS-запись A домена на IP сервера; если используете AAAA, IPv6 также
   должен вести на этот сервер. Укажите домен без `https://` в `SITE_DOMAIN`.
4. Откройте входящие TCP-порты 80 и 443; убедитесь, что они не заняты.
5. Оставьте `BIND_ADDRESS=127.0.0.1` и запустите:

```bash
docker compose -f compose.yaml -f compose.https.yaml up -d --build
```

Caddy получает и обновляет TLS-сертификат автоматически. Сайт доступен по
`https://ВАШ-ДОМЕН/`, админка — `https://ВАШ-ДОМЕН/#/admin`.
Для этой установки во всех последующих командах также используйте оба `-f`.

Для временного доступа по IP без HTTPS можно установить `BIND_ADDRESS=0.0.0.0`
и открыть TCP-порт `HTTP_PORT`. Не передавайте реальные пароли и данные
кандидатов через незашифрованный HTTP; предпочтителен вариант с HTTPS.

## Обновление и остановка

```bash
docker compose up -d --build
docker compose stop
```

Данные находятся в именованном томе `app_data` и сохраняются при пересоздании
контейнера. **Не выполняйте `docker compose down -v`: это удаляет данные.**
Используйте один экземпляр приложения: JSON-хранилище не рассчитано на несколько
параллельных контейнеров.

При первом запуске контент копируется из образа, список кандидатов пустой.
Локальные отклики не включаются в образ. Данные браузера GitHub Pages не
переносятся автоматически. Изменения исходного `content.json` при обновлении
образа не заменяют данные уже созданного тома.

## Резервная копия

Сделайте копию перед обновлениями. Остановка исключает запись во время копирования.

```bash
mkdir -p backups
docker compose stop app
docker compose cp app:/app/backend/data ./backups/data
docker compose start app
```

Папка содержит персональные данные: храните её приватно, вне публичного сайта
и Git-репозитория. Для повторной копии используйте новую папку с датой.

Восстановление из копии:

```bash
docker compose stop app
docker compose cp ./backups/data/. app:/app/backend/data/
docker compose start app
```

После переноса убедитесь, что файлы доступны на запись пользователю контейнера
с UID/GID `10001`. Не меняйте владельца всего проекта или системных каталогов.
